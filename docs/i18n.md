# Internationalization (i18n)

## Supported languages

| Locale  | Language           | Shown in the picker as |
| ------- | ------------------ | ---------------------- |
| `en`    | English (fallback) | English                |
| `ja`    | Japanese           | 日本語                 |
| `zh-CN` | Simplified Chinese | 简体中文               |

Users switch language in **Settings → Language**. The interface updates immediately, without a reload.

## Language selection

`shared/i18n/locales.ts#resolveLocale` applies these rules in order:

1. **An explicit choice.** `localStorage["anime-horizon-locale"]` is written only when the user picks a language in Settings. A browser-derived language is never stored, so a first-time visitor keeps following their browser until they choose.
2. **The browser's languages, in preference order** (`navigator.languages`):
   - `ja`, `ja-*` → `ja`
   - `zh`, `zh-CN`, `zh-SG`, `zh-Hans-*` → `zh-CN`
   - `en-*` → `en`
   - Traditional Chinese (`zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant-*`) is not offered yet, so it is skipped and the next browser language is tried.
3. **Otherwise `en`.**

`I18nProvider` keeps `<html lang>`, `document.title` and the meta description in sync with the active locale. In Japanese, CSS switches the sans-serif stack to Noto Sans JP, because the default Noto Sans SC would draw kanji with Chinese glyph forms (`styles.css`).

## Where translations live

```text
shared/i18n/
  locales.ts          supported locales, resolution, persistence
  translate.ts        createTranslator(): t(), plurals, number/score formatting; Messages and MessageKey types
  I18nProvider.tsx    React provider (state, <html lang>, title)
  useI18n.ts          useI18n() hook and context
  messages/en.ts      English source of truth (defines every key)
  messages/ja.ts      Japanese, typed as Messages
  messages/zh-CN.ts   Simplified Chinese, typed as Messages
  animeTitle.ts       anime title display policy
  genres.ts           AniList genre → label key
  keys.ts             typed key builders for enum-driven keys (season, status, reaction, airing)
```

### Conventions

- **Keys are semantic dotted paths** (`card.removeAria`, `status.PLAN`), never the visible text.
- **Interpolation.** `{name}` fills a parameter. Numbers are formatted with `Intl.NumberFormat` for the locale, except parameters whose name contains `year`, which are never grouped ("2026", not "2,026").
- **Plurals.** A message written as `{ one, other }` is chosen with `Intl.PluralRules` from the `count` parameter. Japanese and Chinese only need `other`.
- **History dates.** Personal history is stored as locale-independent ISO strings (`shared/schemas/history.ts`) and formatted only for display with `formatHistoryDate` (`shared/i18n/dates.ts`), showing only the precision the value has ("2019", "June 2019", "Jun 15, 2019"). Unknown dates use `card.history.unknown` (Unknown / 記録なし / 未记录).
- **Scores.** AniList scores (0–100) are shown with `formatScore()` as locale-aware percentages.
- **Services stay language-neutral.** User-visible results come back as codes or structured data, and components translate them:
  - AI errors → `AIErrorDescription` + `formatAIError`
  - recommendation reasons → `RecommendationReason`
  - SQL import errors → `ArchiveSqlError.code`
  - backup errors → `BackupError.code`
  - catalogue errors → `CatalogueError`
  - Taste Map → `TasteModel` (counts, stances and evidence levels; see `docs/taste-model.md`)

  So switching language re-renders everything already on screen, including open toasts.

- **Decorative eyebrows stay English.** The small-caps labels (`*.eyebrow`, such as "Season Focus") are English in every locale by design, and are still routed through messages so they can change later.
- **Never translated:** user notes, imported data, AniList titles, synopses, studio names and other catalogue content.

### Completeness checks

- **Compile time.** `ja` and `zh-CN` are typed as `Messages`, which is derived from `en`. A missing or extra key, or a call to `t()` with an unknown key, fails `npm run typecheck`.
- **Unit tests** (`tests/i18n.test.tsx`) check that:
  - all locales have the same key set;
  - no message is empty;
  - interpolation parameters match English;
  - plural shapes match;
  - no new hard-coded Chinese UI text appears in `App.tsx` or `components/`. The allowlist only covers a title-matching regex.
- **At runtime**, a missing key falls back to English, then to the key itself. In development it also logs a warning once.

## Taste Map wording

Taste Map copy (`tasteMap.*`) avoids statistical terms and verdicts. Stances read as everyday phrases — "Mostly enjoyed / Mixed / Mostly not for you" (好きなことが多い / 好き嫌いが分かれる / 合わないことが多い; 多为喜欢 / 褒贬不一 / 多为不喜欢) — and evidence is shown as counts ("18 watched · 14 liked · 1 disliked") plus a "Limited evidence" tag (手がかり少なめ / 证据有限), never as percentages. "Taste Map" is 好みのマップ in Japanese and 口味地图 in Chinese. A missing reaction is always shown as `reaction.unrated` (No rating yet / まだ評価していません / 未标记感受), and NEUTRAL as `reaction.NEUTRAL` (It was okay / ふつう / 一般).

The analysis report's section titles were changed to match: "How you watch (interpretation)" and "Release eras" replace "Viewer profile" / 成分侧写 and "Your golden era".

## Recommendation wording

Recommendation reasons (`recommendations.reason.*`) are templates filled from structured evidence, never AI text. Titles are quoted the way each language normally quotes works: none in English, 「」 in Japanese, 《》 in Chinese. Reactions are named with the same words as on cards (loved / liked; 「とても好き」「好き」; 非常喜欢 / 喜欢), and genres only appear as "enjoyed" when the Taste Map shows them as enjoyed.

## Recall wording

Recall is 思い出クイズ in Japanese ("memory quiz": light, personal) and 看番回忆 in Chinese ("anime-watching memories"). The Journey view switcher reads Timeline / Taste Map / Recall (タイムライン / 好みのマップ / 思い出クイズ; 时间线 / 口味地图 / 看番回忆). Season answers reuse `season.label`. Personal details reuse the card's words: reaction labels, and the note label (ひとこと感想 / 短评).

Phase B4 also removed the `games.*` and `quiz.*` namespaces, the header's `nav.more` / `nav.openMore` / `nav.tasteQuiz` / `nav.games`, the report's `analysis.section.avoid` / `analysis.section.recommendations` / `analysis.filteredNote`, and ten keys that no code referenced. The zh catalogue score label changed from “{score} 推荐度” (which read like a recommendation score) to “AniList 评分 {score}”.

## Destination names

The four top-level destinations (`nav.*`, also used as page titles and in `meta.pageTitle`) were chosen to read as native product navigation rather than literal translations:

| Destination | English  | Japanese     | Simplified Chinese | Notes                                                                                                     |
| ----------- | -------- | ------------ | ------------------ | --------------------------------------------------------------------------------------------------------- |
| Discover    | Discover | 見つける     | 发现               | Short verbs, the convention for a browse tab in each language.                                            |
| My Anime    | My Anime | マイアニメ   | 我的番剧           | 番剧 is the everyday Chinese term for series anime; マイ〜 is the standard Japanese "my list" pattern.    |
| Journey     | Journey  | 視聴のあゆみ | 观看历程           | Describes a personal viewing history, not a ranking or "stats" page. あゆみ avoids the stiffness of 履歴. |
| Settings    | Settings | 設定         | 设置               |                                                                                                           |

Older names that are no longer shown: "Archive" / アーカイブ / 年鉴 for the saved list (the `archive.*` message namespace was removed in Phase B2). The `/archive` URL still works as an alias for `/my-anime`.

My Anime's tabs (`myAnime.tab.*`) match the status labels on cards (`status.*`): Watching / Plan to Watch / Completed / All, 視聴中 / 見たい / 視聴完了 / すべて, 在看 / 想看 / 已看完 / 全部. (Simplified Chinese used 追更 for WATCHING until Phase B3A; it was changed to 在看 because the status isn't limited to currently airing anime.) Journey's year-only group (`journey.yearOnly`) says plainly that only the year is known: "Sometime in {year}", {year}年のどこかで, {year} 年（具体时间未记录）. Its `{year}` parameter is never digit-grouped.

## Adding a language

1. Add the locale to `SUPPORTED_LOCALES` and `LOCALE_NATIVE_NAMES`, and extend `matchBrowserLocale` in `shared/i18n/locales.ts`.
2. Create `shared/i18n/messages/<locale>.ts` exporting a `Messages` object, and register it in `MESSAGES` in `translate.ts`. TypeScript will list every key still missing.
3. Add a `TITLE_ORDER` entry in `animeTitle.ts`, and an `AI_OUTPUT_LANGUAGE` entry in `services/geminiService.ts`.
4. Add font rules in `styles.css` if the script needs a specific font.
5. Add the locale to the `LOCALES` matrix in `e2e/i18n.spec.ts`. The completeness tests pick it up automatically.

## How anime titles are displayed

The UI language never invents or machine-translates titles. Only AniList's `native`, `romaji` and `english` fields are used (`shared/i18n/animeTitle.ts`):

| UI locale | Main title                | Subtitle             |
| --------- | ------------------------- | -------------------- |
| `ja`      | native → romaji → English | romaji, else English |
| `en`      | English → romaji → native | native, else romaji  |
| `zh-CN`   | native → romaji → English | romaji, else English |

AniList has no Chinese title field, so the Chinese UI shows the Japanese original, as it always has. A subtitle is omitted when it would repeat the main title. Archive search still matches all three title fields in every locale. Sorting by title uses the displayed title and the locale's collation.

## AI output language

- **Prompts stay in Chinese.** Each prompt appends an output-language block (`AI_OUTPUT_LANGUAGE` in `services/geminiService.ts`) asking for user-visible prose in the UI language: tags, analysis, viewing style, release eras and reflective questions. It also gives a per-language tag-length rule and title convention.
- **JSON field names never change** (`tags`, `analysis`, `questions`, …). The prompt says so explicitly, and the Zod schemas are language-independent.
- **Caching is per language.** Successful taste reports are cached in memory per locale (`analysisByLocale` in `App.tsx`):
  - Generating in English and then switching to Japanese sends a new request and never shows the English report as Japanese.
  - Switching back reuses the English report.
  - If a report exists only in another language, the modal says so and offers to regenerate.
  - Failures are never cached (Phase A).
  - A report pasted back from ChatGPT is filed under the current locale, because its prompt was built in that language.
- **Archive data is unaffected.** Statuses, reactions and notes don't depend on language, so switching never changes or invalidates stored data.

## Not yet localized

- **Developer-facing text.** Server responses, console logs, AI prompt instructions and SQL comments are not user-facing and stay as they are.
- **READMEs.** `README.md` (English) and `README.zh-CN.md` describe the product in two languages; there is no Japanese README.
